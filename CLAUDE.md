# oeperweb — repo map for Claude

Static website (oeper.dev, deployed via GitHub Pages / Jekyll workflow) plus small
Node services run **on a phone in Termux**, exposed through a Cloudflare Tunnel.
No build step for the site: plain HTML/CSS/JS, one `.html` per page.

## Layout
- Root `*.html` — pages (index, ai, feed, files, messages, videos, chess, admin, storage, …).
  `css.css` / `js.js` are the shared styles/scripts. `eosat.html`, `lds.html` are huge — avoid reading them whole.
- `shared/` — shared JS modules used by pages (account, topnav, footer, ai-*, settings-sync, theme-*, upload-queue, report, …).
- `data/` — `articles.json`, `downloads.json`.
- `forum-server/` — Node/Express server meant for Termux (see its README.md, which is long and authoritative):
  `upload-server.js` (uploads, files, folders, report relay to a Discord *webhook*), `storage-admin.js`
  (quotas/trash/moderation), `ai-proxy.js`, `aio.sh` (interactive Termux menu: pull, .env, start/stop server + cloudflared),
  `shortcuts/start-oeper-server.sh` (Termux:Widget one-tap start). Local JSON "databases" are gitignored (hold user emails).
- `forum-server/dbhosting.js` — Discord bot hosting, mounted by `upload-server.js` under `/dbhosting/api/*` (owner / `DBHOSTING_ALLOWED_EMAILS` only).
  Bots run as child processes (own env, crash backoff, restored on server boot); data in gitignored `dbhosting-bots/` + `dbhosting-state.json`.
  Billing: prepaid hosting credits in gitignored `dbhosting-credits.json` (`added - used` = quota; 0 stops the account's bots, an owner allocating more resumes them).
  Metered per minute: slots (1/2/4 × 192 MB) × `DBHOSTING_CREDITS_PER_SLOT_DAY` (10). Owners' bots are free. Hosting credits are this feature's own quota unit (oeper.dev has no
  currency any more): only owners can allocate them, approve and revoke accounts from the page (`/admin/*`); there is no user top-up. Non-owners only see their own bots.
  Per-bot settings (name, auto-restart, Discord status/rotating activities) live in `state[id].settings`; `dbhosting-presence.js` is preloaded into Node bots
  and applies the status to discord.js via a watched `<id>.presence.json` (see README "Settings tab").
  "Bot maker" bots (`kind:'maker'`) are no-code: `bot.config.json` + shared engine in `forum-server/bot-engine/` (`logic.js` validation/presets shared by server
  and engine, `handlers.js` command logic, `index.js` runtime); discord.js installed once in `forum-server/node_modules`. UI = "maker" tab in `dbhosting.html`.
  `GET /dbhosting/api/status` is public (counts only) and feeds a row on `status.html`.
  UI is `dbhosting.html` (oeper.dev/dbhosting). Add any new `/dbhosting/api` route to the router in `dbhosting.js`, not `upload-server.js`.
- `forum-server/app-release.js` — receives new Searver Android APKs from the dev PC (`PUT /app-release`, header `x-release-key` = `RELEASE_KEY` in .env, off when unset); saves to gitignored `app-releases/Searver.apk`, which the Searver app (same phone) reads for updates. `GET /app-release/info` is public (version only).
- epic AI app downloads (ai.html prompt, tools.html card) point at the GitHub release `oeper/releases` → `epicai-latest/EpicAI.apk` (refreshed by `./gradlew publishUpdate` in the app project); the phone server's `/app-release/epic/*` route still exists but is no longer what the site links to (it 404s unless the server is updated and an APK was PUT to it).
- `forum-server/remote-proxy.js` — forwards `/searver-remote/*` to the Searver app's remote-control server on `127.0.0.1:8799` (so another phone can control this one through the tunnel). Auth is the app's own HMAC header; this file only proxies and sets `x-real-ip` from `cf-connecting-ip`; 502 JSON when the app isn't answering.
- `cf-ai-worker/` — Cloudflare Worker replacing `ai-proxy.js` (Workers AI); deploy with `npx wrangler deploy`.
  Epic AI tools (offered only with the settings.html "epic AI" switch on): `create_document` (oneWord) and `create_discord_bot` (`botTools: true`) — the worker only streams a
  `createBot` SSE event; `ai.html` `aiCreateBot()` then creates the bot via `/dbhosting/api` (POST /bots, PUT /bots/:id/file, POST /install) as the signed-in user. Token never in code (DISCORD_TOKEN env).
- epic AI usage limits + codes (worker `cf-ai-worker/src/`): `ledger.js` = SQLite Durable Object `Ledger` (binding `LEDGER`, one instance "main"): per-person daily **tokens**
  (guest 10k / free 50k / plus 240k defaults, editable), a shared neuron pool (7,000/day of the 10k free Workers AI neurons, 20% reserved for oeper+), promo codes vs product keys
  (keys: prefix + random, default 1 use; promos: chosen word, many uses, once per person; scope `epicai` = site+app, `site` = site only), brute-force lockouts. `auth.js` verifies
  the Firebase ID token (Google JWKS, WebCrypto); owners = `OWNER_EMAILS`. Only requests with `app:"epicai"` are counted; ledger errors fail open. Guests (signed out) also get only 5 messages/day (`limits.guestMessages`, editable in promo-admin; reason `messages` in the 429); owners (`OWNER_EMAILS`) are unlimited; `quiet` internal/agent calls don't count as messages. Reasoning ("thinking") only runs when `wantsThinking` says the prompt needs it. Grants can also be a boost (`boostPercent` + `boostDays`: % more daily tokens for N days, `limitFor()` in ledger.js); `SEED_PROMOS` there holds code-defined promos created on first use (EAIRELEASE: 10% more usage for 30 days, redeemable until 2026-10-31 UTC). Long chats: the worker refuses any non-system message over 4000 chars, so clients shorten huge old messages and fold older turns into an AI-written summary (`compactChat` in ai.html, `compactHistory` in the app's ChatViewModel). Routes: `/api/usage`, `/api/redeem`, `/api/admin/*`. Each streamed turn ends with a `{usage:{in,out,exact}}` SSE event (tokens read/written; `exact` = the model reported them, else estimated) that the Android app stores with timings for its "Response details" (Speed, Tokens, Time, Ended); clients that do not know it ignore it.
  Pages: `plus.html` (oeper+), `usage.html` (plan + meter + pictures), `redeem.html` (enter a code, history), `promo-admin.html` (owners: codes, keys, limits, stats) — all via `shared/codes-api.js`.
  Product codes: all oeper.dev product codes start with `OPD-` (single product `opd` in the ledger config; `DEFAULT_CONFIG.products`). The config is persisted the first time limits are saved, so `promo-admin.html` itself PUTs `products: {opd: …}` on load when no product has prefix OPD (works without redeploying the worker); keys made earlier as `EAI-…` still redeem (redeem never checks the prefix). The page never writes a product code out: the generated list, the "All codes" table and the DOM show `OPD-••••-••••-••••` (rows are looked up by index, `shownCodes`), and only Copy / Copy all / Download .txt hand out the real code. Promo and product-code forms both take Plus days, bonus tokens, and a "% more daily usage for N days" boost. Local test: `cd cf-ai-worker && npx wrangler dev --var TEST_AUTH:1 --port 8788`, then open `promo-admin.html?api=http://127.0.0.1:8788&as=<owner email>` from the static server.
  Feedback: `POST /api/feedback` (guests ok, 5 per hour per person/IP, kinds bug|idea|legal|rating|other; optional `FEEDBACK_WEBHOOK` secret forwards to Discord) stores `fb:*` rows in the
  Ledger DO (newest 500); owners read/mark/delete via `/api/admin/feedback`. Pages: `feedback.html` (public form) and a Feedback card in `promo-admin.html`. Legal pages `terms`/`privacy` cover epic AI;
  `CONSENT_VERSION` in `shared/account.js` re-asks consent when the terms change (bumped to '4' on 2026-10-14 for oeper+/pictures/credits removal; the Android app has its own `Consent.VERSION`).
  `wrangler deploy` is NOT automatic: the user must run `cd cf-ai-worker && npx wrangler deploy` (new DO migration `v1-ledger`). `ai.html` only sends the token header once `GET /api/usage` answers (old worker safe).
  `ai.html` is styled like the Android app (epic AI mark SVG `EPIC_MARK_SVG`, greeting + suggestion chips `EMPTY_STATE_HTML`, flat answers, pill composer, sidebar chat search); favicon is `epicai-icon.svg`; **the epic AI logo is the user's face SVG everywhere** (viewBox `0 0 381 486`: two 80x300 rounded bars at x=2 and x=297 plus a stroked smile `M40 421C140 454.333 240 454.333 340 421`, stroke 80 round; class `epic-mark`/`epic-face`, `currentColor`) — never the Material `auto_awesome` sparkle: ai.html, index.html "Ask epic AI", settings.html, `shared/one-ai.js` (button, panel head, home button), the one-suite app-menu tile (`one-src/*/shared/core.js` `a.html`, rebuild with `one-src/bundle.py`), desktop app (index/quick/app.js, `tools/make-icons.js` → assets) and the Android app (`EpicMark`, overlay `Mark`, launcher/monochrome/notification vectors). The app icon is that face on a #DCDCDC→#767676 vertical gradient; 429 limit errors show the worker's message as-is (`err.isLimit`).
  `ai.html` streaming: the answer is not re-rendered while the reader is touching/flinging the page (`readerIsScrolling`), otherwise the DOM swap cancels the scroll. Auto-follow (`following` flag, `scheduleScroll`): the page eases to its own bottom (the sticky composer sits in flow after the messages) while an answer streams; wheel-up/touch/keys up turn it off, scrolling back near the bottom turns it on, sending a message turns it on.
- `cf-auth-proxy/` — Worker (`npx wrangler deploy`) routed on `oeper.dev/download/*` (serves the epic AI app files from GitHub releases under oeper.dev, so the site never links to GitHub) and on `oeper.dev/__/auth/*` + `/__/firebase/*` (forwards to the firebaseapp.com host). The auth part is currently UNUSED: `authDomain` in `shared/account.js` was set to `oeper.dev` (so Google's chooser says "oeper.dev") and reverted on 2026-10-13 because Google answered redirect_uri_mismatch — `https://oeper.dev/__/auth/handler` must be added as an authorized redirect URI on OAuth client `882911814752-tg9rcbej8dnokmov6q63b8bdd9knpsa1` in Google Cloud project `oepernet-1683535959256` (owned by an account the user could not find; the user gave up on it). Switch `authDomain` back to `oeper.dev` only after that URI is registered.
- `desktop/epicai/` — the epic AI desktop app (Electron, Windows + macOS). It is NOT the website in a frame: `app/` is its own bundled UI (index.html, style.css, app.js, acct.js = Firebase auth/chats/memory, api.js = worker calls, prompt.js = system prompt + chat compaction, md.js = the markdown parser COPIED from ai.html — re-copy if it changes there, quick.html = quick-entry box). `main.js` serves `app/` to the window as `https://oeper.dev/__epic/*` via `session.protocol.handle('https')` (everything else is forwarded with `net.fetch`), so the UI runs with oeper.dev's origin and the worker, uploads and Firebase accept it without CORS changes. Native: screen capture (`captureScreen` IPC → desktopCapturer, hides the window first), quick-entry window on Ctrl/Cmd+Shift+Space (`quick-preload.js`), mic permission, tray, notifications, login item, theme. Screenshots are sent once and never stored/synced (message gets `screen:true` only). The model can answer `<<screen>>` to ask for a look (same protocol as the Android app); setting "Ask me first / Look automatically / Never". Chats sync via Firestore `aiChats/{email}` and memory via `aiMemory/{email}` (same as the site). Voice = `/api/transcribe` on the worker (Whisper turbo, signed-in only, 40/hour). Google sign-in can't happen in Electron: `acct.signIn()` → `window.epicDesktop.signIn()` opens `app-auth.html?mode=desktop` in the system browser, which returns a Google ID token via `epicai://desktop-auth` (`signInWithCredential`). The window must be shown by a `did-finish-load` fallback as well as `ready-to-show` (the latter never fired once). `.github/workflows/build-epicai-desktop.yml` (Run workflow or tag `epicai-desktop-v*`) builds Windows (nsis+portable) and macOS (dmg+zip, arm64+x64, ad-hoc signed) into the release `epicai-desktop-latest` with version-less names; the site serves them as `oeper.dev/download/*` (cf-auth-proxy worker) so no GitHub link is on the site. Local: `cd desktop/epicai && npm i && npx electron .` (add `--remote-debugging-port=9333` to drive it over CDP; the `Page.captureScreenshot` only works once the window is actually shown). Mac builds only run in CI and have never been run on a real Mac; screen capture there needs the Screen Recording permission. The Searver desktop app (macOS target added) lives outside this repo in `AndroidStudioProjects/Searver/desktop`.
- `one/`, `one-src/` — "One" office suite (`bundle.py` builds `one/index.html` from `one-src/*`). Edit `one-src`, then rebundle. Apps: oneWord/Sheet/Slide/Idea/Site/Draw/PDF. **oneDraw** (`one-src/onedraw`, storage `od-lib`/`od-doc-<id>`, files `.onedraw`, sync type `draw`): infinite whiteboard on one `<canvas>` (`js/board.js` tools/selection/rendering, `js/model.js` doc+undo+templates, `js/app.js` pages panel/ribbon/backstage). Handwriting→text (`js/ink.js`): strokes are drawn to a black-on-white PNG and sent to the worker `/api/chat` as a vision message (`quiet:true`, not counted), after a one-time consent (`od-ink-ok`); tools "Write to text" (auto-converts 1.7 s after the last stroke), "Convert to text" on a selection, and a Writing pad. Only works from oeper.dev (worker CORS). After editing `shared/core.js`, copy it into every app's `shared/` (oneDraw also holds `m3.css`). Phone server needs `git pull` + restart for `draw` cloud sync. **Installable app (PWA):** `one/manifest.json` + `one/sw.js` (scope /one/, network-first page, cached shared scripts/fonts) + `one/icons/*.png` (made by `node one-src/pwa/make-icons.js`); `bundle.py` injects the manifest link/SW registration into the oeper.dev build only; `shell.html` has the Install button/`#install` modal (beforeinstallprompt, iOS/Safari instructions) and `launchQueue` file handling (`file_handlers` in the manifest → `importFiles`). Bump `VERSION` in `one/sw.js` if the cached file list changes.
- `firestore.rules` — Firestore security rules (auth is Firebase; owner accounts = admins).

- **One: fonts and oneWord editing** (2026-10-14): `ONE.fonts` in `one-src/shared/core.js` (copied into every app like the rest of core) is a catalogue of ~80 Google Fonts (sans, serif, display, handwriting, mono) that the font pickers of oneWord (`W.FONTS`), oneSlide (`S.FONTS`) and oneSheet (`X.FONTLIST`) append to; `ONE.fonts.fill(select, list)` builds the grouped `<select>`. In patch scripts use function replacers (`s.replace(a, () => b)`): a string replacement turns `$$` into `$` and `$'` into text.
- **epic AI memory file** (built 2026-10-14): besides the quick `facts` array, `aiMemory/{email}` holds `profile` (a markdown file of `## Section` + `- bullet` lines, max 6000 chars, one section max 1200), `profileUpdated` and `learn` (bool, on unless false = the "let epic AI learn about me" switch). The model keeps it with the worker tool `update_profile(section, content)` (replaces that whole section, empty = delete), streamed as an SSE `{profile:{section,text}}` event that the client merges (`applySection` in `shared/ai-memory.js`; identical copy in `desktop/epicai/app/ai-memory.js`; Kotlin port = `Memory` in the Android app's `Chats.kt`) and writes to Firestore; the prompt block (file + how/when to learn + the one-short-question-now-and-then rule + what never to store) is `profilePrompt()` / `Memory.promptBlock()`. With learn off the client drops `remember`/`updateMemory`/`profile` events and tells the model not to use the tools. UI: ai.html memory panel (textarea + save + learn switch + "get to know me" which starts an interview chat), desktop account dialog, Android Settings › Your memory file. `CONSENT_VERSION` is '3' and Android `Consent.VERSION` 2 because terms/privacy now describe it; the worker needs `npx wrangler deploy` for the `update_profile` tool.

- **epic AI remembers other chats** (2026-10-15): `shared/ai-recall.js` (`recallPrompt(chats, currentId, query)`, pure; identical copy in `desktop/epicai/app/ai-recall.js`) looks through the person's OTHER chats on this device (titles, summaries, messages) for the words of what they just typed and appends the best 3 chats (2 passages each, max ~1700 chars) to the system prompt; a vague "what did we talk about last time" lists the latest chats instead. - **epic AI pictures** (2026-10-14): worker tool `generate_image` (offered only when the client sends `imageTools: true`, the person is signed in and the call isn't `quiet`) and `POST /api/image` (One suite) both go through `makeImage()` in `cf-ai-worker/src/images.js`. Standard = `@cf/black-forest-labs/flux-2-klein-4b` (Workers AI, multipart FormData input, `{image: base64}` out, 1 MP max, charged as 104 neurons), best = `google/nano-banana-2.1` (third party, billed in dollars through the Cloudflare account's AI Gateway credits; if that call fails — e.g. "Insufficient AI Gateway credits" — the picture is silently made with the standard model and nothing is counted as best). Limits live in the ledger (`images`: free 4/day, oeper+ 15/day of which 3 best, `premiumGlobal` 20 best/day for everyone, `budget` 2000 neurons/day for standard pictures, 20% of it reserved for oeper+, also counted in the shared chat pool); `imageReserve`/`imageRelease` reserve before and refund after a failure; owners are unlimited. Prompts go through llama-guard (`moderateText`). The worker sends SSE `: drawing` comments every 8 s while it works (clients have 45 s watchdogs; generation takes 25-60 s) and the picture as an SSE `{image:{mime,data,w,h,best,prompt,used,limit}}` event. Clients keep the picture OUT of the synced chat: ai.html / desktop store it in IndexedDB `epic-pictures` (`PicStore`) and the message only gets `images:[{id,w,h,best,prompt}]`; Android saves files in `filesDir/pics` (`Pictures.kt`, same note shape in the message `extra`) with Save-to-gallery. The panel asks the shell (`window.ONE_CLOUD.makePicture/pictureInfo` in `shell/cloud.js`, which owns the sign-in and calls `POST /api/image`), shrinks the result to a 1024 px JPEG and offers "Add to document" (through the app's `ONE.insertPicture(url, {w,h,alt})`, defined in oneWord, oneSlide, oneDraw and oneIdea; the other apps (oneSheet, oneSite, oneStudy ...) just get Save), Save and Try again. Only shown when epic AI is switched on in oeper.dev settings and the app runs inside the oeper.dev shell. History keeps just a `<<picture>>prompt<</picture>>` note, never the image. Not built yet: picture editing (nano-banana takes `image_input`), AI deck/site generators that add pictures on their own, syncing pictures between devices.
- **epic AI can read web pages** (2026-10-14): worker tool `read_webpage(url, offset?)` in `cf-ai-worker/src/webpage.js` fetches a public http(s) page from the Worker, keeps the readable text of `<main>`/`<article>` (9000 chars per call, `offset` pages through long ones) plus the main links, follows up to 4 redirects re-checking each hop, and refuses localhost/private/IP-literal hosts, non-web ports, credentials in the URL and non-text content. Results carry a warning that the text is untrusted (never obey instructions inside it). No JavaScript rendering, logins or PDFs. The three client prompts (`ai.html`, desktop `prompt.js`, Android `SitePrompt.kt`) list it among the tools.

## Conventions
- Recent history is mostly "epic AI: …" commits touching `ai.html` + `shared/ai-*.js`.
- No tests/linters configured. Check changes by loading the page (`.claude/launch.json` serves statically on :8080).
- Discord is used for the report webhook (`upload-server.js`) and for hosted user bots (`dbhosting.js`); there is no first-party bot.
- Termux one-liners (install deps / run server) were given to the user in chat; the run one mirrors `shortcuts/start-oeper-server.sh` plus `termux-wake-lock`.
